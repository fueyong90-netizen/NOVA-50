# NOVA-50

**From-scratch language model under a strict 50,000,000 trainable-parameter budget.**

Submission for the **Global Innovation Build Challenge V2, Track 01: TECH**.
Official rules verified 2026-09-24 at <https://gibc-v2.devpost.com/rules> —
see [docs/COMPETITION_RULES.md](docs/COMPETITION_RULES.md).

## Competition compliance

| Requirement | Status |
|---|---|
| ≤ 50,000,000 trainable parameters (embeddings + output head included) | **PASS** — 32,937,472 (65.87% of budget) |
| Trained from scratch (no pretrained init / fine-tune / distillation) | **PASS** — random init, see `model/transformer.py` |
| Parameter count script + config in repo | **PASS** — `scripts/count_parameters.py`, `configs/model_nova.yaml` |
| README reports hardware / training time / compute | **PASS** — see Hardware & Compute below (measured values only) |
| Official benchmarks (HellaSwag, ARC-Easy, PIQA, WinoGrande via lm-evaluation-harness) | **NOT RUN** — see `results/benchmarks/lm_eval_report.md` |
| WikiText-103 held-out perplexity | **NOT RUN** — see `results/benchmarks/wikitext103_report.md` |
| Public repo, English documentation | **PASS** (this document) |
| AI assistance disclosed | **PASS** — see below |

**Why two rows say NOT RUN:** this project was developed in a sandboxed
container with no GPU and a network egress allow-list limited to package
registries (PyPI/npm/GitHub/crates.io) — it cannot reach huggingface.co,
where the official benchmark datasets are hosted. Every benchmark script is
fully implemented and was actually executed here; the captured, real error
in each case is a data-download failure, not a missing implementation. See
`docs/COMPETITION_RULES.md` for the full explanation and the exact command
to re-run on a machine with normal internet access.

## Final parameter count
See `results/parameter_report.md` (generated by `scripts/count_parameters.py`,
which exits non-zero if the budget is exceeded — enforced by
`tests/test_parameter_budget.py`):

- **NOVA-50** (`configs/model_nova.yaml`): 32,937,472 trainable parameters
  (65.87% of budget). Conservative accounting (if the tied output head were
  counted as a separate tensor): 37,033,472 (74.07% of budget) — still PASS.
- **Baseline** (`configs/model_baseline.yaml`): 14,974,080 trainable parameters.

## Architecture
One implementation (`model/layers.py`, `model/transformer.py`) parameterizes
both MODEL A (baseline) and MODEL B (NOVA-50), guaranteeing an apples-to-apples
comparison.

| | MODEL A — baseline | MODEL B — NOVA-50 |
|---|---|---|
| Norm | LayerNorm | RMSNorm |
| Position | learned (none — `use_rope: false`) | RoPE |
| Attention | standard MHA | GQA (4 KV heads for 8 Q heads) |
| FFN | GELU, 2 matrices | SwiGLU, 3 matrices |
| Weight tying | no | yes |

## Dataset
**Toy synthetic corpus** (`data/scripts/prepare_toy_corpus.py`) is used only
for unit tests / CI and small demo training runs — see
[docs/DATASET.md](docs/DATASET.md). The **production data pipeline**
(`data/scripts/download_production_data.py` and downstream scripts, see
[docs/PRODUCTION_DATASET.md](docs/PRODUCTION_DATASET.md)) targets public
datasets explicitly permitted by the rules (TinyStories, FineWeb, The Pile,
or similar) but could not download them from this container — **NOT RUN**.

## Training
Custom PyTorch training loop (`training/train.py`): AdamW, warmup + cosine
decay, gradient clipping, gradient accumulation, checkpointing/resume,
automatic hardware detection, and a real, step-driven **curriculum learning**
integration (`training/curriculum.py`) that dynamically switches the active
data mixture mid-run — see `docs/ABLATIONS.md` for a real measured
curriculum-vs-fixed-mixture comparison.

**Full-scale training of `configs/model_nova.yaml` (32.9M params) on
production data has NOT been run** — no GPU and no production corpus in this
environment. All demo/ablation experiments below use miniature configs
(150K-350K params) on the toy corpus to prove the pipeline works end-to-end.

## Evaluation
- `evaluation/run_lm_eval.py` — official lm-evaluation-harness wrapper
  (HellaSwag, ARC-Easy, PIQA, WinoGrande). Installed and integrated; data
  download fails in this environment — see `results/benchmarks/lm_eval_report.md`.
- `evaluation/wikitext103.py` — WikiText-103 held-out perplexity. Same
  status — see `results/benchmarks/wikitext103_report.md`.
- `evaluation/benchmark_contamination.py` — n-gram overlap check between
  training data and official eval sets. NOT RUN for the same reason; the toy
  corpus is synthetic and contains no real-world text by construction.
- `evaluation/reasoning.py` — **INTERNAL DEBUGGING BENCHMARK, NOT A GIBC
  BENCHMARK.** Simple arithmetic exact-match, used only as a development
  sanity check.
- `evaluation/perplexity.py` — toy-corpus perplexity, for pipeline
  validation only, never reported as the official WikiText-103 number.

## Installation
```bash
git clone <repo>
cd NOVA-50
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pytest -q
```

## Quick start
```bash
python scripts/reproduce.py          # full toy pipeline, end to end
python scripts/competition_audit.py  # readiness check
python scripts/security_scan.py      # secret scan
```

## Inference
```bash
python inference/generate.py --checkpoint experiments/nova/matched_run/best.ckpt \
    --model_config configs/model_nova_matched_demo.yaml \
    --prompt "Question: What is 4 plus 5? Answer:" --max_new_tokens 20
```

## Web demo
```bash
python inference/server.py --checkpoint experiments/nova/matched_run/best.ckpt \
    --model_config configs/model_nova_matched_demo.yaml --port 8000
# then open web/index.html
```
Shows parameter count, architecture, and benchmark status — displays
**NOT RUN** rather than placeholder numbers wherever a real result is absent.
